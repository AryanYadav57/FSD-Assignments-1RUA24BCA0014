The Idea &
Vision

Synapse is a networked note-taking web application built for people who think fast and want their tools to keep up — a modern "Second Brain" that connects ideas, not just stores them.

Traditional note-taking apps treat notes as isolated files stored in folders. But human thought does not work that way — ideas connect, reference each other, and evolve over time. Synapse was designed around this reality. Instead of folders, it uses wikilinks and a Graph View to let users see, at a glance, how all their ideas are interconnected.

The core philosophy is zero friction. The moment an idea strikes, a user should be able to capture it with a single keyboard shortcut — no file picking, no folder navigation, no saving dialogs. Ideas land in an Inbox and can be refined into proper Notes at the user's own pace.

💡

Inspiration: Synapse draws conceptual inspiration from tools like Roam Research and Obsidian, but reimagines them as a web-first product — accessible on any device, with no local files, real-time sync, and a beautiful editorial interface.

The Problem it Solves

Students and knowledge workers lose an enormous amount of time and insight because their ideas are scattered across different apps, notebooks, and browser tabs. Synapse gives them one unified, intelligent space where every thought is connected and instantly searchable.

Target Users

Students, researchers, writers, developers, and anyone who works with information and needs to build a personal knowledge base over time.

State Management with Zustand

Zustand replaces Redux with a minimal, hook-based API. Each domain has its own store. The notesStore holds all the user's notes in memory, allowing instant UI re-renders when any note is created, updated, or deleted — no loading spinners needed for in-memory operations.

Preventing Hydration Mismatches (SSR Safety)

Because Expo uses Static Site Generation (SSG), the HTML is pre-rendered on the server without knowing the visitor's screen size. A custom useIsMobile() hook was built to prevent React Hydration errors (Error #418) — it defaults to desktop on the server, then safely switches to the correct mobile layout after the client has mounted, preventing the blank-white-screen crash on phones.

Backend & Database

Database Schema — notes Table

Column Type Description
idPK uuid Auto-generated unique identifier for each note.
user_idFK uuid References auth.users. Used by RLS to enforce data isolation.
title text The plain-text title of the note.
content jsonb The full Tiptap JSON document AST. Stored as JSONB for efficient querying.
content_text text Flattened plain-text version of the note for fast full-text search indexing.
status text One of 'inbox', 'note', 'archived', or 'trashed'.
is_pinned boolean Whether the note is pinned to the top of the dashboard.
is_public boolean If true, the note is accessible via a public share URL.
share_slug text The URL-friendly identifier for the shared note (e.g., my-ideas-2026).
updated_at timestamptz Auto-updated timestamp. Used to sort notes from most recently edited.

Row Level Security (RLS) — Zero-Trust Security

The database enforces strict user isolation at the database level itself. No matter what API call is made, PostgreSQL evaluates the user's JWT token and only returns or allows modification of rows where user_id = auth.uid(). 

-- Example RLS policy on the notes table
CREATE POLICY "Users can only see own notes"
  ON notes FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Public notes visible to all"
  ON notes FOR SELECT
  USING (is_public = true);

Data Flow &
UI Design

Optimistic Update Flow (Note Saving)

1

User types in the editor

The Tiptap editor fires an onUpdate callback with a fresh JSON document on every keystroke.

2

Zustand store updates instantly

The note is immediately patched in the in-memory Zustand store. The UI re-renders with no latency — the user sees their changes instantly.

3

Debounced sync to Supabase

A 500ms debounce timer fires a background PATCH request to the Supabase REST API. The user sees a "Saving…" indicator.

4

PostgreSQL persists the AST

The JSON document is saved to the content JSONB column. A separate content_text column stores a flattened string for search.

Deployment &

Build & Deployment Pipeline

STEP 01

Environment Variables

Supabase URL and Anon Key are stored in a .env file with the EXPO_PUBLIC_ prefix, baking them into the static JS bundle at build time.

STEP 02

Static Export

Running npx expo export -p web generates a dist/ directory with static HTML per route and a single optimised JavaScript bundle.

STEP 03

SPA Routing Fix

A _redirects file (/* /index.html 200) tells Netlify to serve index.html for all routes, enabling client-side navigation.

STEP 04

Netlify Deploy

The dist/ folder is dragged onto the Netlify dashboard. Netlify serves it globally via CDN on a free custom subdomain.

🔐

Supabase Auth Setup: The deployed site URL (https://synapsenotess.netlify.app) is whitelisted in Supabase's Authentication → URL Configuration to allow secure OAuth redirects and email-based authentication flows.

Key Technical Challenges Solved

1. React Hydration Mismatch (Error #418): SSG pre-renders HTML for desktop; mobile clients see a different layout, causing a fatal React crash and blank white screen. Fixed by building a custom useIsMobile() hook that defers the mobile-check to post-hydration.

2. Editor Dark Mode in iframe: The Tiptap editor runs inside a 'use dom' iframe which has its own separate document. The app's data-theme="dark" attribute on the outer page does not propagate into the iframe. Fixed by passing an isDark prop from the parent and applying it to the iframe's document.documentElement.
