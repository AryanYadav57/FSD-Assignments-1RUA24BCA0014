# Spawn.gg: AI Game Generator (PRD + Implementation Plan)

> Name: **Spawn.gg** (gg = "good game"; every game starts at a spawn point, and here it starts from a prompt).
> Tagline: *"Type it. Spawn it. Play it."*
> Logo concept: a map-pin/spawn-point marker shaped like a game controller, with a small spark inside. Colors: dark navy background, neon green or violet accent.
> Inspired by the "Sandbox" AI game generator YouTube tutorial. Recreated with a different stack (React Native + NVIDIA API) for CIE2.

---

## PART 1: PRODUCT REQUIREMENTS DOCUMENT

### 1. Overview
Spawn.gg is a mobile app where a user types a text description ("a flappy-bird style game with a cat") and gets a playable 2D game generated by an AI model, running inside the app.

### 2. Goals
- Turn a text prompt into a playable game in under 2 minutes, with extra time available for a more polished result.
- Demonstrate a full-stack flow: mobile app, backend, AI API, database, auth.
- Be finishable within the CIE2 timeline and explainable line by line.

### 3. Non-Goals (out of scope)
- External 3D/game engines and libraries (Three.js, Unity). A prompt may request a self-contained WebGL/WebGL2 game without external dependencies.
- Payments or subscriptions.
- Multiplayer.
- Publishing to the App Store / Play Store.

### 4. Target Users
- Students and casual users who want to quickly make simple games without coding.
- Evaluators viewing a demo.

### 5. User Stories
| ID | As a user, I want to... | So that... |
|----|-------------------------|------------|
| U1 | sign up / log in | my games are saved to my account |
| U2 | type a prompt describing a game | the AI builds it for me |
| U3 | see a loading state while it generates | I know it's working |
| U4 | play the generated game inside the app | I can try it instantly |
| U5 | save games to a gallery | I can replay them later |
| U6 | ask for changes ("make it faster") | I can refine the game |
| U7 | delete a saved game | I can manage my library |
| U8 | share a game link (stretch) | friends can play it |

### 6. Functional Requirements
**FR1 Auth:** Email/password sign up and login. Sessions persist.
**FR2 Prompt screen:** Text input, example prompt chips, "Generate" button.
**FR3 Generation:** App sends the prompt to the backend. Backend calls the NVIDIA LLM and returns a single self-contained HTML file.
**FR4 Validation:** Backend checks the output is valid HTML, contains no external network calls, and is under a size limit. It retries once on failure.
**FR5 Player:** Generated HTML renders in a WebView with a "Restart" and "Back" control.
**FR6 Gallery:** List of the user's saved games (title, prompt, date). Tap to play, swipe or button to delete.
**FR7 Refine:** "Modify" sends the previous HTML plus a change request to generate a new version.
**FR8 Errors:** Friendly messages for rate limits, timeouts, and bad output.

### 7. Non-Functional Requirements
- **Security:** The NVIDIA API key lives only on the backend, never in the app. WebView runs generated code with restricted settings (no file access, no navigation away).
- **Performance:** Generation timeout of 120s. Show progress states.
- **Reliability:** Rate limit requests per user (for example 10 per hour) to protect free API credits.
- **Usability:** Works on Android and iOS via Expo Go.

### 8. Tech Stack
| Layer | Choice |
|-------|--------|
| Mobile app | React Native + Expo, Expo Router, TypeScript |
| Game display | `react-native-webview` |
| Backend | Node.js + Express |
| AI | NVIDIA API (OpenAI-compatible endpoint), coding-focused model |
| Auth + DB | Supabase (or Firebase) |
| Backend hosting | Render or Railway (free tier) |

### 9. Architecture
```
[React Native App]
   | 1. prompt + auth token
   v
[Express Backend] --2. verify token--> [Supabase Auth]
   | 3. chat completion request
   v
[NVIDIA API] --4. HTML game--> [Backend: validate]
   | 5. save game
   v
[Supabase DB] --6. HTML + id--> [App: WebView player]
```

### 10. Data Model
**games**
- `id` (uuid, pk)
- `user_id` (fk to auth user)
- `title` (text)
- `prompt` (text)
- `html` (text)
- `parent_id` (uuid, nullable, for refined versions)
- `created_at` (timestamp)

### 11. API Endpoints
| Method | Route | Purpose |
|--------|-------|---------|
| POST | `/api/generate` | `{ prompt }` returns `{ id, title, html }` |
| POST | `/api/refine` | `{ gameId, instruction }` returns new game |
| GET | `/api/games` | list user's games |
| GET | `/api/games/:id` | fetch one game |
| DELETE | `/api/games/:id` | delete a game |

### 12. Core Prompt Design (system prompt draft)
> You are a game developer. Return ONLY one complete, self-contained HTML file containing HTML, CSS, and JavaScript. Use an HTML5 canvas. No external libraries, images, fonts, or network requests. The game must work with touch controls AND keyboard, fill the screen, show a score, and have a restart option. Output no explanation and no markdown fences.

### 13. Risks and Mitigations
| Risk | Mitigation |
|------|------------|
| AI returns broken or unsafe code | Validate output, retry once, sandbox the WebView, block external URLs |
| Free API credits or rate limits run out | Per-user rate limit, cache results, test with short prompts |
| Slow generation | Progress UI, timeout, smaller max tokens |
| Scope too large | Follow phases; Phases 1 to 4 form a complete MVP |
| API key leaks | Backend only, `.env` never committed |

### 14. Success Criteria
- 8 out of 10 test prompts produce a playable game.
- Full flow works end to end on a real phone: login, prompt, play, save.
- You can explain every layer during evaluation.

### 15. Originality Additions (mention in CIE2)
Different stack from the original video (React Native + NVIDIA instead of Next.js + Claude), gallery, refine feature, output validation, and rate limiting.

## PART 2: IMPLEMENTATION PLAN

Time estimates assume a few hours per day. Adjust to your deadline. **Phases 1 to 4 = MVP.**

### Phase 0: Setup (0.5 to 1 day)
- [ ] Install Node.js, VS Code, and Expo Go on your phone.
- [ ] Create a GitHub repo with two folders: `/app` and `/server`.
- [ ] Create accounts: NVIDIA (build.nvidia.com, get an API key), Supabase, Render or Railway.
- [ ] Test your NVIDIA key with a tiny script and confirm the endpoint and model name in their docs.
- [ ] Add `.gitignore` and `.env.example`.

**Done when:** a script prints an AI response from NVIDIA.

### Phase 1: Backend Core (1 to 2 days)
- [ ] Initialize Express server with `cors`, `dotenv`, `openai` SDK.
- [ ] Point the OpenAI SDK at NVIDIA's base URL with your key.
- [ ] Build `POST /api/generate` with the system prompt.
- [ ] Add output cleanup (strip markdown fences) and validation (starts with `<!DOCTYPE` or `<html`, has `<canvas` or `<script`, no `http` script or link tags, size limit).
- [ ] Add retry on validation failure.
- [ ] Test with Postman/curl; save outputs as `.html` and open in a browser.

**Done when:** 8 of 10 prompts give a working game in your browser.

### Phase 2: Mobile App Shell + Player (1 to 2 days)
- [ ] Create the Expo app (TypeScript, Expo Router).
- [ ] Screens: Home (prompt), Player, Gallery (placeholder).
- [ ] Prompt input, example chips, Generate button, loading state.
- [ ] Call the backend (use your laptop's local IP for testing).
- [ ] Player screen with `react-native-webview` using `source={{ html }}`.
- [ ] Lock down the WebView (block navigation, disable file access).
- [ ] Handle touch input and screen orientation.

**Done when:** you type a prompt on your phone and play the game.

### Phase 3: Auth + Saved Games (1 to 2 days)
- [ ] Set up the Supabase project, `games` table, and row-level security (users see only their rows).
- [ ] Login and signup screens with Supabase Auth; persist the session.
- [ ] Backend middleware to verify the token on every route.
- [ ] Save the game on generate; build Gallery screen (list, open, delete).
- [ ] Add `GET`, `DELETE` routes.

**Done when:** you log in on a fresh install and see your saved games.

### Phase 4: Deploy + Polish (1 day)
- [ ] Deploy the backend to Render or Railway; set env variables there.
- [ ] Point the app to the deployed URL.
- [ ] Add rate limiting (`express-rate-limit`) and a request timeout.
- [ ] Friendly error states and empty states.
- [ ] Test on a real phone using mobile data.

**Done when:** the whole flow works without your laptop. **This is your MVP.**

### Phase 5: Refine Feature (1 day)
- [ ] Add "Modify" button on the Player screen.
- [ ] `POST /api/refine` sends the old HTML plus the instruction; saves with `parent_id`.
- [ ] Show version history in the gallery (optional).

### Phase 6: Stretch Goals (only if time remains)
- [ ] Shareable web link that plays a game in a browser.
- [ ] Prompt templates by genre (racer, shooter, puzzle, platformer).
- [ ] Streaming progress from the backend.
- [ ] Dark mode, app icon, splash screen.
- [ ] Simple usage stats screen.

### Phase 7: Evaluation Prep (1 day)
- [ ] Record a 2 to 3 minute demo video as a backup.
- [ ] Prepare a one-page architecture diagram (use the one above).
- [ ] Prepare answers: Why is the key on the backend? How do you validate AI output? How does the WebView sandbox work? What did you change from the original video?
- [ ] Clean the README with setup steps and screenshots.
- [ ] Test on a second device and a poor network.
